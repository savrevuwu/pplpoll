## 2. Database / schema updates (to be added in the gameplay migrations, not yet written)

- `games`: add `mode` (`solo`, `mystery`, `h2h`, `teams`, `ffa`), `format` (`classic`, `speed`), `duration_ms`, `clock_remaining_ms` (frozen during pauses), `series_id`, `tournament_match_id`.
- `game_sides` (new): one row per competitor — a player in Solo/H2H/FFA, a team in Teams. Holds shared strikes, accepted-guess count, score as **exact counts** (`score_count` / `respondents`), `reached_final_at`, `correct_count`, final `placement`, `outcome`.
- `game_side_members` (new): users on a side; turn rotation order for Classic Teams.
- `guesses`: add `side_id`, `submitted_by` (teammate credit), `share_count` (frozen answer-group count). Unique `(side_id, answer_group_id)` where correct → an answer counts once per team.
- `series` (new): `best_of` (3/5), sides, rounds won, status. Rounds = `games` with `series_id`; unique poll per series.
- `tournaments`, `tournament_entries`, `tournament_matches` (new): kind (individual/team), size (4/8/16), format, bracket position, round, advancing side, placement.
- `mystery_challenges` (new): game id, objective type + parameters, validated-against snapshot id, result.
- `player_stats` (new, rebuildable from results): per user × scope (overall / mode / format / tournament kind) counters, streaks (win streak, win-days streak, solo success streak), rarest correct guess (`count`, `respondents`, guess id, at).
- `rarest_guess_record` (derived view or table) + badge assignment recomputed on any new record or invalidation.
- Percentages are stored as **exact integer fractions** (answer count / respondents in the frozen snapshot), never as rounded decimals. Comparisons use cross-multiplication.

## 3. Matchmaking, timing and scoring changes

- **Queues:** separate queues per (mode × format × best-of). H2H needs 2, Teams 4 (two sides of 2), FFA 3–6 (start rule for a partially filled FFA lobby: existing "first available compatible players", minimum 3).
- **Timers:** one server match clock per game (Classic 120 s, Speed 60 s). Clock stops at pauses/outages and resumes from the stored remaining time. Match ends when the clock hits 0 or every side is finished (3 strikes, guess cap, or — see G4 — reaching 60%).
- **Classic:** alternating turns between sides; in Teams the submitting teammate rotates. Turn order and what happens when a side doesn't guess on its turn — G5.
- **Speed:** all sides guess at once. In Teams, two teammates sending the same answer at the same moment: the first one the database commits counts, the other gets "Already guessed" (row lock on the side).
- **Scoring:** each side's score = sum of its unique correct answer groups. Duplicate answer for a side = "Already guessed": no points, no attempt, no strike. Opposing sides score the same answer independently.
- **Ranking (all modes):** higher exact score → earlier time it was reached → fewer correct guesses → otherwise a true tie. FFA places 1st/2nd/3rd with ties kept.
- **Privacy:** opponents and spectators never see guessed words. Teammates see their own team's words (needed to avoid repeats).

Engineering decisions (no owner input needed):

- Rarest Correct Guess shows only the percentage (e.g. "0.84%") — never the poll or the answer, so nothing hidden leaks. Only valid completed games count; no-contest, invalidated and cheating games are excluded and the badge is recomputed when a record is invalidated.
- "Time reaching final percentage" = server time of the guess that gave the side its final score. If a side scores 0, it never reached anything; two 0% sides fall through to a tie.
- Display precision for percentages: 2 decimals, but all comparisons use the exact stored fraction.
